# 动一动

把分散在不同平台的跟练视频收藏到同一个页面，少翻一次收藏夹，早点开始运动。

**[打开动一动，直接使用](https://d1d-public.vercel.app/)**

无需注册，也不用配置数据库。默认把收藏保存在你的浏览器里；需要跨设备同步时，再部署自己的版本并接入 Supabase。

## 为什么做这个

我收藏的跟练视频散落在不同平台。每次想运动，都要先打开 App、翻收藏夹、筛选找到对应视频，这些步骤增加了开始运动的阻力。

所以做了这个网页：贴入链接，把常用视频放在同一个画廊里，按标签找到今天想练的内容，点开就开始。这是一个由 AI 辅助开发、正在日常使用的个人工具，不是提供账号和视频托管的商业服务。

## 能做什么

- 批量添加视频链接，识别分享文字里的标题，也可以自己修改标题。
- 尝试获取 Bilibili、YouTube、Vimeo 的标题与封面；获取失败时显示标题占位图。
- 用标签分类、筛选和搜索，每个视频最多选择三个标签。
- 点击封面播放支持嵌入的视频，点击标题打开原网页；小红书和小鹅通直接跳转原网页。
- 编辑标题、链接和标签，删除收藏。
- 导入、导出 JSON 备份；可选 Supabase 云端同步。

## 1. 直接使用：浏览器本地存储

### 添加和查找视频

1. 打开 [动一动公共版](https://d1d-public.vercel.app/)。
2. 在视频平台点击「分享 → 复制链接」，优先复制并粘贴同时包含标题和链接的完整分享内容，再点本站右上角「添加」。可以一次贴多条，每行一条。
3. 选择标签后保存；不选标签也可以。
4. 用顶部标签或搜索框查找视频，点封面播放。

建议保留分享文字中的标题，例如「【视频标题】 https://…」。这样即使平台接口解析失败，也能使用你贴来的标题。只贴网址也可以，但自动获取标题可能失败；带标题的分享内容不能保证封面一定获取成功。B 站添加时会清理已知追踪参数，保留分 P 和播放时间参数。

**这时不用填写「同步设置」。** 收藏保存在当前设备、当前浏览器、当前网址下，不会自动上传到网站部署者的视频库。分享网站链接也不会把你的收藏分享出去。

本地保存不等于离线播放：标题解析、封面加载和视频播放仍会访问本站 API 或第三方平台。

### 备份和换设备

1. 点页脚「导出」，下载一个 `.json` 备份文件。
2. 把文件传到另一台设备，在那台设备打开网站。
3. 点「导入」，选择文件，确认后追加收藏。

备份包含标题、链接、标签和封面地址，不包含视频文件或同步密钥。重复链接会跳过，不覆盖已有视频。当前支持单个文件最多 5 MB、2000 条。

**这是手动搬运，不是自动同步。** 两台设备之后的修改各自独立。旧版 TXT 可以粘贴到「添加」窗口，但其中没有标签信息。

清除网站数据、换浏览器或换网址，都可能看不到原来的本地收藏。隐私浏览模式也不适合长期保存。请定期导出；如果页面提示存储已满或不可用，关闭或刷新前先导出备份。

## 2. 自行部署：Supabase 跨设备同步

想让手机、平板和电脑看到同一份收藏，可以部署自己的版本。需要三个账号：GitHub、Supabase、Vercel；不需要先购买域名，也不需要注册本网站账号。

可以简单理解为：**GitHub 放代码，Vercel 运行网站，Supabase 保存你的云端收藏。**

### 第一步：Fork 一份代码

在本仓库页面右上角点击 **Fork → Create fork**，把代码复制到自己的 GitHub 账号下。

Fork 是推荐方式，后续方便接收原项目更新；并不是唯一方式，也可以把代码放进自己的新仓库。下面以 Fork 为例。仅仅 Fork 不会自动创建网站，也不会复制作者的数据库、密钥或收藏。

### 第二步：创建自己的 Supabase 数据库

1. 登录 [Supabase](https://supabase.com/)，新建一个项目。
2. 等项目准备好，打开 **SQL Editor**，创建一个查询。
3. 打开仓库中的 [supabase/schema.sql](supabase/schema.sql)，将完整内容放入查询中，点击 **Run**，创建收藏表。
4. 在项目的连接信息或设置中找到 **Project URL**，以及 **API Keys** 中的服务端凭据，留待下一步填写。

本项目当前按 `service_role` key 配置服务端请求。若界面显示新旧两组密钥，请查找 legacy API keys 中的 `service_role`；不要选择 `anon` 或 publishable key，也不要把数据库密码当成 API key。密钥类型说明见 [Supabase 官方文档](https://supabase.com/docs/guides/getting-started/api-keys)。

上面的 SQL 用于新部署；已经有数据的旧项目不要为了照着教程重建数据库，应先备份并核对表结构。脚本会启用 RLS，不需要额外开放匿名用户的读写权限。

### 第三步：用 Vercel 部署网站

1. 登录 [Vercel](https://vercel.com/)，选择 **Add New → Project**，连接 GitHub。
2. 导入你刚刚 Fork 的仓库，不是作者的原仓库。
3. Framework Preset 选择 **Other**，Root Directory 保持仓库根目录，Build Command 填 `npm run build`，Output Directory 填 `public`。
4. 在 **Environment Variables** 中添加以下三个变量，再点击 **Deploy**。

| 变量名（照抄左列） | 值填什么 |
| --- | --- |
| `SUPABASE_URL` | 第二步获取的 Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 第二步获取的服务端 `service_role` key，仅供服务器使用 |
| `APP_WRITE_TOKEN` | 你自己生成的一段随机长密码，例如用密码管理器生成至少 32 位随机字符串 |

**`APP_WRITE_TOKEN` 是你给自己的网站设置的同步密码，不是 Supabase 提供的 key。** 保管好它，拿到它的人能够查看、添加、修改和删除你的云端收藏。不要把任何真实密钥放入 GitHub 文件、截图或发给 AI。

部署完成后，Vercel 会给你一个 `xxx.vercel.app` 地址，这就是你自己的网站。之后修改环境变量，要重新部署才会生效；正式网站使用的变量应配置在 Production 环境。参考 [Vercel 部署文档](https://vercel.com/docs/git) 和 [环境变量说明](https://vercel.com/docs/environment-variables)。

不配置这三个变量也能使用本地收藏，但不能连接云端。不要仅用 GitHub Pages 代替这套部署：本项目的 `/api/*` 需要服务端运行，纯静态托管不能完整提供这些能力。

### 第四步：在设备上连接同步

1. 打开**你自己部署的网址**，点页脚「同步设置」。
2. 输入第三步设置的 `APP_WRITE_TOKEN`，点击「连接」。不是输入 `SUPABASE_SERVICE_ROLE_KEY`。
3. 在其他设备打开同一个网址，输入同一同步密码。

连接成功后，画廊显示云端收藏，添加、编辑、删除会保存到 Supabase。浏览器会记住同步密码，通常无需反复输入；其他设备打开或刷新页面时会读取云端数据，不是实时协作编辑。

「断开同步」会回到该浏览器的本地收藏，不会删除云端视频。本地与云端是两份独立收藏，不会在后台自动合并。云端连接失败时可能显示已有缓存，恢复连接后才能修改。

作者网站上的「同步设置」不能接入你的 Supabase 项目；它只连接当前网站部署时配置的数据库。因此需要在你自己部署的网址上使用同步。

### 已经用了本地收藏，如何改成云端同步？

**情况 A：还在同一个网址、同一个浏览器。**

连接云端成功后，检测到本地收藏会弹出「检测到本地有 X 个视频，是否导入云端？」。选择「导入云端」即可；选择「暂不导入」则不会上传。

导入只追加新链接，跳过重复项，不覆盖云端已有视频，也不删除本地收藏。完成后其他设备连接同一个云端库，就能看到这些视频。

**情况 B：之前用作者网站，现在有了自己的新网址。**

1. 在原网址、本来使用的浏览器中，点「导出」备份本地收藏。
2. 打开自己的新网址，先在「同步设置」连接云端。
3. 点「导入」选择备份文件，确认目标为云端收藏。

不同网址不能互相读取浏览器本地数据，因此这一步需要手动搬运一次。以后连接云端使用，就不用为了跨设备反复导入导出了。仅在新网址导入但未连接同步，文件仍会保存到那个网址的本地收藏。

### 可选：绑定自己的域名

在 Vercel 项目的 **Settings → Domains** 添加域名，然后到域名服务商的 DNS 页面，按 Vercel 显示的类型、名称和值添加记录。只绑定子域名时，不要删除主域名已有的博客或邮件记录，不要照抄旧教程的固定 IP。

换域名前先导出本地收藏。云端数据不受换域名影响，但新网址需要重新输入同步密码。分享预览由 `npm run build` 自动生成，优先使用当前 Vercel 项目的生产域名，未提供时使用该次部署地址，不再写死作者的个人域名。绑定或更换域名后重新部署以更新预览。

如需指定分享地址，可在对应项目添加可选环境变量 `SITE_URL`（完整的 `https://你的域名`，不含路径和参数）；它不是密钥，也不影响同步。Vercel 需允许构建访问系统环境变量。未配置任何地址的本地构建不输出网页地址与图片地址预览标签，避免误用他人的网址。参见 [Vercel 系统环境变量](https://vercel.com/docs/environment-variables/system-environment-variables#vercel_project_production_url)。

### 不熟悉部署？可以让 AI 帮忙

可以将自己 Fork 后的仓库交给 AI，并这样提问：

> 请根据这个仓库的 README，带我一步步部署到 Vercel 并接入我自己的 Supabase。我没有编程经验，请先检查代码和配置，再告诉我每一步在哪里操作。密钥由我在控制台填写，不要把真实密钥写进代码或提交到 GitHub。保留本地收藏，不要修改已有数据库，遇到迁移或删除先征求我的同意。

## 使用限制与隐私

- 本工具只保存链接和相关信息，不下载或托管原视频，不绕过平台登录、付费或版权限制。
- 标题和封面可能因为网络、反爬或平台变化获取失败；B 站优先使用含 BV 号的完整链接，暂不展开短链接。
- 内嵌播放的清晰度、自动播放和登录状态由视频平台限制。播放不了时，可以点击标题打开原网页。
- 本地收藏不会自动上传成云端视频库，但获取标题、封面和播放时会向本站服务或第三方发送网络请求，不是完全离线或无外部请求的工具。
- 同步密码保存在当前浏览器中，请勿在公共设备上保持连接。它是单个部署的访问密码，不是每人一个账号，也不提供多人私有库托管。
- 免费托管服务可能有流量、调用量或暂停限制，不保证永久免费、持续在线。公开部署者应关注服务用量与费用告警；基础接口限流不能限制全部部署费用。
- JSON 是可读的收藏备份，分享文件会暴露其中的标题和链接，请自行保管。

## 给开发者和 AI 的说明

技术栈：原生 HTML / CSS / JavaScript、Node.js、Vercel Serverless Functions、Supabase PostgreSQL。没有前端框架或 npm 运行时依赖；界面参考 [Animal Island UI](https://github.com/guokaigdg/animal-island-ui)，未安装其 React 组件库。

使用 Node.js 22 或更新的受支持版本，在项目根目录运行：

```bash
npm run dev
```

打开 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)，端口可通过 `PORT` 修改。无需环境变量即可试用本地收藏；不建议双击 HTML，以免 `/api/*` 和图标路径无法正常工作。

本机调试云端时，将 `.env.example` 复制成 `.env` 并自行填写三个变量。`npm run dev` 不自动读取 `.env`，请改用：

```bash
node --env-file=.env server.mjs
```

检查、测试和构建：

```bash
npm run check
npm test
npm run build
```

修改根目录的 `index.html`、`style.css`、`script.js` 后运行构建，生成 `public/` 中的副本；不要单独编辑副本或删除 `public/` 内的图标。根目录 `api/` 是 Vercel Functions，不应复制到静态目录。现有 Vercel 项目不必为了跟随新部署教程直接更改配置，应先核对当前设置。

```text
index.html / style.css / script.js  页面源文件
server.mjs                         本地服务器与本地 API
api/                               Vercel API
lib/                               元数据、封面代理和输入校验
public/                            构建副本与图标
supabase/schema.sql                数据库结构
tests/                             本地与模拟 API 测试
docs/security-review.md             安全检查记录和剩余风险
```

已知技术边界：本地服务器的 PATCH 当前只处理标题和分类，Vercel API 还支持链接及播放信息更新；快捷键不能保证控制第三方 iframe；没有多设备冲突合并机制。进一步安全事项见 [安全检查记录](docs/security-review.md)。

旧版升级：原有个人云端仍使用 `default` 记录，不需要为本次本地优先改动迁移数据库。旧 `?library=...` 共享库入口已停用，其他库记录没有被删除，但不再通过当前 API 访问。
